# 01. Telegram-бот записи клиентов

> **Демо-проект.** Барбершоп «Борода» вымышленный, услуги и цены в `business.json` — примерные. Реальных клиентов и записей здесь нет.

## Какую задачу бизнеса решает

Салон, барбершоп, стоматология, мастер на выезде — у всех одна боль: запись идёт через личные сообщения и звонки. Администратор отвлекается, клиенты пишут ночью и не получают ответа, время путают и записывают двоих на одно и то же.

Этот бот берёт запись на себя:

- клиент сам выбирает услугу, дату и свободное время, подтверждает запись;
- занятое время не показывается, а двойная запись невозможна;
- владелец сразу получает уведомление в Telegram (новая запись или отмена);
- клиент может посмотреть свои записи и отменить запись;
- администратор одной командой видит список записей на сегодня.

## Что умеет

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | приветствие, адрес, меню |
| `/book` | все | запись: услуга → дата → время → подтверждение |
| `/my_bookings` | все | список своих записей, кнопки отмены |
| `/cancel` | все | прерывает запись, а если запись не начата — предлагает отменить одну из существующих |
| `/today` | админ | записи на сегодня со ссылками на клиентов |

Ограничение: не больше 3 активных записей на одного клиента (меняется в `business.json`), чтобы бот не засоряли.

## Как запустить

Нужен Python 3.10+ и токен бота.

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
2. Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot).
3. Запустите:

   **Windows:** двойной клик по `start.bat` (или `start.bat` в терминале).
   **Mac / Linux:** `bash start.sh`

   При первом запуске скрипт сам создаст окружение, поставит зависимости и создаст файл `.env`.
4. Откройте `.env`, впишите `BOT_TOKEN` и `OWNER_ID`, снова запустите `start.bat` / `start.sh`.
5. Напишите своему боту `/start`. Владелец (`OWNER_ID`) тоже должен хотя бы раз нажать `/start`, иначе Telegram не даст боту написать ему первым.

Остановить: `Ctrl+C`.

## Как настроить под свой бизнес

Всё про бизнес лежит в [`business.json`](business.json) — код трогать не нужно:

- `name`, `address`, `phone` — что видит клиент;
- `work_start`, `work_end`, `slot_minutes` — рабочий день и шаг сетки времени;
- `days_off` — выходные (0 = понедельник, 6 = воскресенье);
- `days_ahead` — на сколько дней вперёд открыта запись;
- `timezone` — часовой пояс бизнеса (важно, если бот стоит на зарубежном сервере);
- `services` — услуги: название, цена, длительность в минутах;
- `demo_notice` — пометка про демо; для настоящего клиента оставьте пустую строку `""`.

Секреты (`BOT_TOKEN`, `OWNER_ID`, `ADMIN_IDS`) лежат только в `.env`. Файл `.env` не попадает в git, образец — `.env.example`.

## Как устроено

```
bot/
  main.py        запуск (python -m bot.main)
  app.py         сборка диспетчера aiogram
  config.py      чтение .env и business.json
  db.py          SQLite: записи, проверка пересечений, отмена
  slots.py       расчёт свободного времени (чистые функции)
  keyboards.py   inline-кнопки
  formatting.py  даты по-русски, тексты записей
  notify.py      уведомления владельцу
  handlers/      booking.py — диалог записи, admin.py — /today, fallback.py — «устаревшие кнопки»
tests/           автотесты
business.json    услуги и расписание
```

Технологии: Python, aiogram 3 (FSM для диалога), SQLite через aiosqlite.

Двойная запись исключена тремя способами: показываем только свободное время, перед сохранением проверяем пересечения в транзакции `BEGIN IMMEDIATE`, а в таблице есть уникальный индекс на активные записи.

## Тесты

```bash
python -m venv .venv
.venv\Scripts\activate          # Mac/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
pytest
```

Тесты проходят полный диалог через aiogram с подставным Telegram: сеть и токен не нужны.

## Ограничения (честно)

- Один специалист на всё расписание. Если нужны несколько мастеров с отдельными графиками — это отдельная доработка (поле «мастер» в записи и в слотах).
- Напоминаний клиентам за день до записи пока нет — можно добавить.
- Состояние диалога хранится в памяти: если бот перезапустить посреди записи, клиент нажмёт старую кнопку и получит «кнопка устарела, нажмите /start». Сами записи в SQLite при этом не теряются.
- Запись не привязана к телефону: связь с клиентом идёт через Telegram.

## Деплой

Бот работает через long polling, отдельный публичный адрес не нужен. Подойдёт любой дешёвый VPS или бесплатный хостинг, где можно держать запущенный Python-процесс. Базу `bookings.db` нужно хранить на постоянном диске.
