# 04. ИИ-ассистент в Telegram для бизнеса (мини-версия)

> **Демо-проект.** Компания «Борода» вымышленная, база знаний в `knowledge/faq.txt` — пример. Это мини-версия: она показывает принцип, а не заменяет полноценную службу поддержки.

## Какую задачу бизнеса решает

Клиенты задают одни и те же вопросы: адрес, график, цены, как отменить запись. Отвечать на них вручную долго, ночью никто не отвечает, а вопрос теряется в переписке.

Бот отвечает на такие вопросы сам, по базе знаний, которую ведёт владелец обычным текстовым файлом:

- отвечает по тексту компании и **не выдумывает** то, чего в базе нет: в этом случае честно говорит «не знаю» и отправляет к живому оператору;
- **прямо говорит, что он ИИ**, а не человек: в `/start`, в инструкции для модели и по прямому вопросу;
- помнит последние реплики диалога, поэтому понимает уточнения вроде «а сколько это длится?»;
- ограничивает число сообщений на человека в сутки и длину вопроса, чтобы расходы на модель не выросли из-за спама;
- модель и ключ меняются в `.env`, код трогать не нужно.

## Как запустить

Нужен Python 3.10+ и токен бота.

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
2. Запустите:

   **Windows:** двойной клик по `start.bat`.
   **Mac / Linux:** `bash start.sh`

   При первом запуске скрипт сам создаст окружение, поставит зависимости и создаст файл `.env`.
3. Откройте `.env`, впишите `BOT_TOKEN`, снова запустите `start.bat` / `start.sh`.
4. Напишите боту `/start`.

По умолчанию стоит `LLM_PROVIDER=mock` — **режим без нейросети**: бот находит подходящий фрагмент базы знаний и цитирует его. Бесплатно и без ключей, хорошо для проверки поиска. В ответе при этом есть пометка «[режим без ИИ-модели]».

### Подключить настоящую модель

В `.env`:

```
LLM_PROVIDER=openai
LLM_API_KEY=ваш_ключ
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
```

Подойдёт любой провайдер с OpenAI-совместимым API: OpenAI, OpenRouter, DeepSeek, локальная Ollama и другие. Меняются только адрес, ключ и название модели (актуальные названия смотрите в документации провайдера; доступность провайдера зависит от вашей страны). Примеры адресов — в `.env.example`. Ключ — это секрет: он живёт только в `.env`, а `.env` не попадает в git.

## Как подключить свою компанию

1. Замените содержимое `knowledge/faq.txt` своим FAQ. Формат: блоки через пустую строку, один блок — один вопрос с ответом. Пишите вопросы словами, которыми спрашивают клиенты («сколько стоит», «как добраться»), и вставляйте синонимы.
2. В `.env` поменяйте `COMPANY_NAME` и `OPERATOR_CONTACT`; `DEMO_NOTICE` поставьте пустым.
3. При желании подправьте правила ассистента в `bot/prompts.py`.

## Как это устроено

```
вопрос клиента
   ├─ лимит на сегодня не исчерпан? ── нет → вежливый отказ, контакт оператора
   ├─ поиск нужных блоков в faq.txt (по словам, без нейросети)
   ├─ инструкция + найденные блоки + последние реплики диалога → модель
   └─ ответ клиенту; реплики и счётчик сохраняются в SQLite
```

```
bot/
  main.py        запуск (python -m bot.main)
  config.py      все настройки из .env
  knowledge.py   загрузка faq.txt и поиск по нему
  prompts.py     инструкция для модели (правила, честность про ИИ)
  assistant.py   лимит, поиск, память, вызов модели
  llm.py         клиенты модели: OpenAI-совместимый и mock
  storage.py     SQLite: память диалога и счётчик сообщений
  handlers.py    команды и сообщения
knowledge/faq.txt   база знаний (демо)
tests/              автотесты
```

Технологии: Python, aiogram 3, openai SDK (для любого совместимого API), SQLite.

Команды: `/start` — о боте и лимитах, `/reset` — забыть диалог, `/operator` — контакт живого оператора.

## Тесты

```bash
python -m venv .venv
.venv\Scripts\activate          # Mac/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
pytest
```

Тесты не ходят в сеть и не требуют ключа: проверяют поиск по базе, лимит, память, поведение при сбое модели и сквозной диалог через aiogram на подставном Telegram.

## Ограничения (честно)

- Поиск по базе знаний простой: по словам с отбрасыванием окончаний. Для FAQ на несколько десятков блоков этого хватает; для большой базы нужны эмбеддинги и векторный поиск.
- Качество ответов в режиме `openai` зависит от модели и не проверялось на живом ключе в этой сборке: автотесты проверяют обвязку, а не ум модели. Перед сдачей клиенту прогоните 20–30 реальных вопросов.
- Диалоги хранятся в `assistant.db` на вашем сервере. Клиент может стереть их командой `/reset`. Если соберёте реальные данные клиентов, подумайте об уведомлении об обработке данных.
- Ассистент не записывает клиентов и не принимает оплату — только отвечает и направляет к оператору (можно связать с проектом 01).
